# AGENTS.md

Guidance for coding agents (Codex, Claude Code) and other devs working in this repo.
`CLAUDE.md` only imports this file, so edit this one.

## What this repo is

artsdata-orion loads arts websites into Artsdata, using only the JSON-LD each
website publishes. Each source is one GitHub workflow that crawls the site,
commits the result to `output/`, and registers it on the Artsdata Databus as an
artifact. Artsdata then loads that artifact into a data feed graph,
`http://kg.artsdata.ca/culture-creates/artsdata-orion/<artifact>`.

Sites loaded for CAPACOA are in `artsdata-stewards/artsdata-orion`, not here.
A source that needs custom code or outside collaborators gets its own
`artsdata-planet-<name>` repo.

## Layout

- `.github/workflows/<site>.yml`: one workflow per website, almost all using
  `culturecreates/artsdata-pipeline-action@v4`. `caller-custom.yml` is a
  manual one-off run that takes its inputs at dispatch time.
- `sparql/<site>.sparql`: optional per-site transform, passed to the action as
  `custom-sparql`.
- `output/`: crawl results, written and committed by the workflows.
- `src/`: Python and Ruby scripts for the non-crawler sources (ISNI, DBpedia,
  MusicBrainz, OpenStreetMap, Google KG, organization logos), each run by its
  own workflow.
- `.agents/skills/`: skills for the tasks below. `.claude/skills` is a symlink
  to it, so there is one copy; add new skills under `.agents/skills/`.

## Skills

- `artsdata-pipeline`: add, test, run or debug a website workflow (selectors,
  sitemaps, `html-extract-config`, failed runs).
- `artsdata-automint`: turn auto-minting on or off for a graph.
- `artsdata-reload-graph`: reload a graph from its existing Databus artifact
  without re-running the workflow.

Use the matching skill instead of working from memory. The last two call
nebula's own code (`~/repos/culturecreates/nebula`) rather than copying its
SPARQL or API calls.

## Conventions

- **Pull before pushing.** Workflows commit to `main` all the time ("Add data
  generated by the script"), so use `git pull --rebase origin main` before you
  push.
- **Don't hand-edit `output/`.** Fix the workflow or its SPARQL and re-run it.
- **Push SPARQL before running.** Workflows load `custom-sparql` from the raw
  file on `main`, so a transform only takes effect after it is pushed.
- **Workflow inputs:** use `artifact-file`, not the deprecated `downloadFile`.
  Always pass `cloudflare-private-key`. The publisher is
  `secrets.PUBLISHER_URI_GREGORY`. Pick an unused minute and weekday for the
  weekly cron so runs don't pile up.
- **SPARQL transforms:** start with a comment block that explains each
  operation, use full IRIs with no `PREFIX`, and separate operations with ` ;`.
  To change a value the JSON-LD already has, extract the replacement under a
  temporary predicate (`https://github.com/culturecreates/artsdata-orion#<name>`)
  in `html-extract-config`, then move it into place and delete the temporary
  triple in the SPARQL. See `sparql/theatrerialto-ca.sparql`.
- **Venues:** single-venue sites often have no usable location in their
  JSON-LD. Add one Place in the transform and link it with `schema:sameAs` to
  the venue's Artsdata ID (or Wikidata, if Artsdata has none) so it
  reconciles instead of minting a new place.
- **Event types:** map to Artsdata event type concepts
  (`http://kg.artsdata.ca/resource/<Concept>`) with `schema:additionalType`.
  When a site has no categories but only hosts one kind of event, hard-code
  the type in the transform.

## Production

Dispatching a workflow, turning on auto-minting and reloading a graph all
change production Artsdata. Do them only when asked, and say what was done.
Minted Artsdata IDs are permanent, so check the data before turning
auto-minting on.
